# Open Source Roadmap

The ladder from "never contributed" to "paid OSS programs".

## Level 0 — Setup
- [x] Git + GitHub CLI configured
- [x] Achievements visibility set to Public on profile
- [ ] SSH key added to GitHub (nicer than HTTPS tokens)

## Level 1 — First contact (docs & typos)
Real repos, trivial fixes. The point is learning the PR workflow, not the diff.
- Find: search GitHub for `label:"good first issue" is:open language:javascript`
- Or fix docs in tools already used in your own projects' `package.json`
- Etiquette: read CONTRIBUTING.md first, comment "I'd like to work on this", keep the PR small

## Level 2 — Real issues (bugs)
- Reproduce the bug, write the reproduction steps in the issue/PR
- Add or adjust a test when the repo has tests
- One logical change per PR

## Level 3 — Events
- **Hacktoberfest** (October): 4 accepted PRs → official swag/trees. Start building rep before October.
- **24 Pull Requests** (December): festive variant

## Level 4 — Structured programs (paid / career-making)
- **Google Summer of Code** — applications ~March/April
- **LFX Mentorship** — quarterly, Linux Foundation projects
- **Outreachy** — twice a year, for underrepresented groups

## Rules that keep maintainers happy
1. Small PRs get merged; big ones rot
2. Match the project's code style, not your own
3. Never spam PRs just for count — maintainers talk to each other
4. Follow up on review comments within a few days
